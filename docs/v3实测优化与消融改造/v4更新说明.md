## 改动内容

### §2.1 全量复验闸

**问题**：轻量 compact 集（少量 case）通过即判 PASS，存在假通过。  
**改动**：轻量通过阈值（≥99.0% match_rate）后，引擎自动替换为最全 case 集（`.json.bak`/`.json.full`，行数最多优先）重跑一遍，finally 恢复原文件。全量结果写入 `validation_result_attempt_N.json` 的 `full_eval` 字段。

`_compute_loop_signal` 语义变更（`scripts/gates/branch_precision.py`）：
- `passed=True` + 有 `full_eval`：全量 100% → PASS；crash 或未满 → `CONTINUE/full_eval_regression`（继续 debug）
- `passed=False` + `mr≥99%` + 全量 100% → 推 near-success 过线为 PASS
- 连续 ≥2 轮全量无改善 → `STOP/nearly_success`（防噪声无限重试）
- 无全量集 / 闸关：维持旧行为（向后兼容）

**涉及文件**：`engine/validate_runner.py`、`scripts/gates/branch_precision.py`

### §2.2 KB 入库判据改全量

**问题**：轻量假通过的成功轨迹会污染知识库。  
**改动**：`_finalize_impl` 前置判断——`full_eval` 存在时，仅 `matched_ratio ≥ 0.95` 且不 crash 的轨迹才入库。旧产物（无 `full_eval`）沿用原判据。

**涉及文件**：`engine/knowledge_finalize.py`

### §2.5 KB 命中率追踪

**改动**：`spawn_diagnose_agent` 末尾检查注入给 agent 的 KB top_titles 中哪些被其 `final_response` 引用，结果追加到 `precision_tuning/kb_usage_trace.json`（字段：`injected_titles`、`cited_titles`、`citation_rate`）。

**涉及文件**：`engine/agent_backend.py`

### §3 消融 toggle 机制

所有 toggle 以 `ABLATE_` 为前缀的 env 变量控制，子进程自动继承，无需代码改动，详见下方消融实验说明。

| 变量 | 关闭的组件 | 落点 |
|---|---|---|
| `ABLATE_FULL_EVAL=1` | 全量复验闸 | `validate_runner._full_eval_enabled()` |
| `ABLATE_FORENSICS=1` | forensics 取证步 | `next_action._round_sequence` |
| `ABLATE_GATE_A=1` | audit (Gate-A) 步 | `next_action._round_sequence` |
| `ABLATE_LOOP_GUARD=1` | N6 退化早停 + nearly_success 防重试 | `next_action` + `branch_precision` |
| `ABLATE_ANTICHEAT=1` | 反作弊/AST/C++ 扫描 | `scripts/gates/common.run_common` |

## 消融实验

批跑脚本通过 `--ablate-profile <arm>` 统一控制消融。脚本内部将 profile 展开为对应 env 变量，经 `docker exec -e` 传入容器，引擎代码无需任何改动。

```bash
bash utils/run_ascendc_debug_batch_cc.sh \
  --task-manifest <manifest.json> \
  --output-dir <out_dir> \
  --ablate-profile <arm>
```

### 可用 arm

| `--ablate-profile` | 关闭的组件 | 对应 env |
|---|---|---|
| `full`（默认） | 无，完整系统 | — |
| `no_fulleval` | 全量复验闸 | `ABLATE_FULL_EVAL=1` |
| `no_forensics` | forensics 取证步 | `ABLATE_FORENSICS=1` |
| `no_audit` | audit / Gate-A 步 | `ABLATE_GATE_A=1` |
| `no_loopguard` | 退化早停 | `ABLATE_LOOP_GUARD=1` |
| `no_anticheat` | 反作弊检查 | `ABLATE_ANTICHEAT=1` |
| `no_kb` | 知识库注入 | `KB_PATH=""` |
| `no_probe` | 插桩 agent | 切换 noprobe agent |
| `baseline` | forensics + loopguard + kb + probe 全关 | 组合以上 |

### 示例：验证全量复验闸 ROI

```bash
# Arm A: 完整系统
bash utils/run_ascendc_debug_batch_cc.sh --ablate-profile full   --output-dir out_full   ...

# Arm B: 关闭全量复验闸
bash utils/run_ascendc_debug_batch_cc.sh --ablate-profile no_fulleval --output-dir out_no_fe ...
```

比较两组 `exit_artifacts` 中 `success_category=clean_kernel_success` 的数量即可量化贡献。
